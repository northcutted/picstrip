## Final acceptance checklist

Before production submission, record results on the exact signed candidate for:

1. iPhone/iPad VoiceOver completion, larger text, RTL and dark appearance; align declarations with what is actually supported.
2. Real camera/document capture, optional name/object models, background/foreground and app-switcher concealment.
3. Photos new/replace/batch save, denied permissions, extension cleaning and expiring edit handoff; cancel during processing.
4. A real receiving app receiving PNG/JPEG/HEIC with the intended redactions and metadata removed.
5. Oldest supported hardware, complex 12/24 MP photos, explicit 48 MP reduction, panoramas, 20–50-photo batches, Shortcuts selections, extension memory and sustained camera thermal behavior.
6. Exact version 1.7.0, new build number, manifest/source/IPA hashes, approved producer provenance, full screenshot inventory and metadata; then approve upload, staging and final production submission separately.

## Approval boundary

The user authorized implementation, branches, push and pipeline validation. The original staged 1.7.0 build 77.1 predates the Photos-save fix and must not be submitted as the corrected build. Existing immutable `v1.7.0` stays recoverable. Review the concrete PRs and checks before approving merge and main-only signed preparation. `publish=false` still uploads to Apple. Upload, publication/staging and production submission need their explicit approval; they have not occurred in this remediation.
